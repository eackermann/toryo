## Invariants (updated)

1. **Read-only turns don't write the project.** Codex: its read-only sandbox. Claude, Cursor, Grok: a read-only mount of the project for the agent and all its children, where the machine supports it (it does here: util-linux 2.41, WSL2). Otherwise the crew panel says so and Claude's permission rules apply. The Codex app: not enforceable, and says so.
2. Snapshots never change the project's git state (now also before the first commit).
3. **Only a terminal, unquoted status line drives the relay**, and the page strips exactly that line.
4. **The relay never loops forever.** Now also when the reviewer omits its status, and on timeouts, which ask the owner.
5. **Restarting loses no work.** Sessions are saved as soon as an agent starts. Messages count as delivered only once the agent started. Checks in progress run again. Only one desk can load a data folder.
6. **A run's results only drive that run.** Superseded or stopped work is recorded but changes nothing. A swap applies before the next building turn.
7. **Nothing reaches a shell, PowerShell or `innerHTML` as code from agent text.** Toast data is base64; Markdown output is built from escaped text with held fragments.
8. The page loads nothing from the internet.

The tests write to `os.tmpdir()`. If your sandbox's `/tmp` is read-only, run with `TMPDIR` pointing at a writable scratch folder. The read-only-mount tests skip themselves (with the reason) where user namespaces aren't available.

## Not verified, and why

- **A real Claude, Cursor or Grok session inside the read-only mount.** The house rules forbid launching them. The mechanism is tested with the fake agent (a Node process, like Claude Code) and a shell. Claude Code under the mount has its own config dir writable and sees the project read-only; if it tries to write inside the project for its own bookkeeping, that turn fails visibly. The fallback is `"readOnlyMount": false` for that agent. The first real read-only Claude turn after the owner restarts Foreman is the live test.
- **Reviewers that run project commands which write into the tree**, such as a TypeScript incremental build-info file, now get `EROFS` in Claude's read-only turns, as they already did under Codex's read-only sandbox. Foreman runs the project's checks itself before each review, so reviewers needn't.
- The mount is a guard against accidental writes, not a security boundary against an agent that sets out to get around it. I deliberately didn't probe ways around it.
- Codex-app cancellation: there is no known way to cancel an app turn from outside, and the house rules forbid experimenting with the app. Foreman now holds the turn instead.
